## 修复结果

### 1. 跑腿发布宽度

`TasksView.vue` 的抽屉宽度改为 `min(520px, 100vw)`。手机上不超过屏幕，桌面保留 520px。回归检查同时测量抽屉和内部输入框，而不是仅检查文档滚动条。

### 2. 弹层与底栏

当前启用页面的业务对话框、跑腿抽屉及手机目录统一使用 `append-to-body`，避免被 `.content-shell` 的层叠上下文限制。未通过盲目增加内部 z-index 处理。

涉及跑腿报名/发布、店铺预约、商品意向/反馈、项目管理/反馈和治理对话框。已有协议弹窗原本就在 body，保留原逻辑。默认关闭的 legacy 金融组件未扩展修改。

实际点击命中检查验证：跑腿表单滚到底部后，提交按钮处于视口内并可收到点击；预约弹窗打开时底栏被遮罩拦住，不能通过底栏切走页面；手机目录仍可跳转并关闭。

### 3. 日期组件

- 运营日期范围在不超过 900px 的布局使用现有 Element Plus 2.14.0 的单月范围面板，仍能选择起止日期；桌面保留双月面板。
- 输入框适配标题卡片的真实内容宽度，而不只是适配屏幕。
- 运营、跑腿截止时间、店铺预约、项目截止时间共用限定的 `responsive-date-popper` 样式。
- 手机日期面板约束宽度和视口高度，内容可内部滚动，确认区保持可达；同时保留不支持 dvh 时的 vh 回退。
- 不修改日期值格式、时区转换或后端接口。

触控选择日期后，测试核对分析请求带上所选起止日期；横屏测试实际点击日期确认按钮，并确认只关闭日历而非关闭预约弹窗。

### 4. 320px 个人信息布局

网格最小列宽改为 `min(320px, 100%)`，保留桌面多列逻辑，允许窄屏卡片缩到父容器可用宽度。320px 回归不再产生整页横向溢出。

### 5. 弱网登录恢复

- API 错误保留明确的 HTTP 状态，恢复登录能区分 401 与其他错误。
- 连接失败、超时、5xx 等临时异常保留令牌，但清空未验证的当前用户，不放行私人页面。
- 登录页首屏展示恢复提示、重试按钮和切换账号入口；重试成功回到原目标页面。
- 明确的 401 仍清除会话并显示普通登录表单，不降低认证要求。
- 用递增的恢复请求序号处理乱序响应。退出、新登录和更新的恢复请求都会使更早的结果失效，即便令牌值相同，也不能把旧用户或旧失败覆盖回来。
- 重试期间用户如果已导航到其他页面，旧重试处理函数不能随后改变新导航。

- 回归脚本语法检查通过。
- 后端、生产 Compose 和生产环境示例配置与基线一致。本轮没有修改后端，因此没有重新执行 Java 测试。

### 实际浏览器检查

通过本机 Vite 开发服务及最终 `dist` 的 preview 服务运行实际前端，所有 `/api/` 响应由浏览器内合成数据提供；无真实账号、后端、数据库或业务写入。

已通过的八类检查：

1. 手机“更多”目录跳转通知并关闭，底栏没有钱包入口。
2. 跑腿抽屉与输入框在 320/360/390/430px 均在屏幕内，桌面仍为 520px。
3. 抽屉提交按钮可点击，预约遮罩拦截底部导航触控。
4. 手机日期范围面板不横向溢出，选择结果正确传给分析接口，桌面双月宽度保持。
5. 844×390 横屏下预约日期确认按钮可见、可触控。
6. 320px 个人信息页无横向溢出。
7. 网络失败保留会话、不显示私人页，手机首屏可重试；恢复成功及 401 清理均正常。
8. 旧恢复请求失败不会覆盖更新的登录状态，也不会改变用户后续导航。

单元测试先复现了网络错误清令牌、重试失败、过期响应覆盖退出/新登录，以及同令牌并发恢复的问题，再验证修复。布局检查也保留了修改前的实际失败结果。

测试脚本初期出现过夹具误匹配 Vite 源模块路径、匹配到隐藏抽屉，以及测量发生在 CSS 过渡未结束时的工具问题，已修正测试前提，未将其算成产品缺陷。一次截图等待外部字体超时后，改用 Chrome CDP 截取实际已渲染画面，并等待同源图片解码；没有通过伪造页面或删除断言掩盖失败。
