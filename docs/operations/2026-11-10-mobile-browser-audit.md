# 手机浏览器适配检查 · 2026-11-10

## 结论

常规浏览页已经具备可用的手机布局，不需要推翻现有设计。但“页面没有横向滚动条”不能证明操作正常：本轮确认了跑腿发布抽屉超宽、底栏覆盖业务弹层、日期选择面板超出屏幕、320px 个人信息页溢出，以及弱网恢复会话时清除登录态的问题。

本轮仅检查和记录，没有修改应用源码、提交 Git、部署、修改数据库或执行真实业务操作。运行中的资金软关闭规则保持不变。

**后续进展：**用户随后授权按本报告修复，已在独立分支完成修改和验证，并经再次授权将 Web 提交 `ed3558e` 发布到线上。修复范围见 [手机适配修复记录](2026-11-10-mobile-browser-fixes.md)，线上证据见 [生产发布记录](2026-11-10-mobile-production-release.md)。本文下方保留修复前的检查证据。

- Chromium 手机模拟：320×568、360×780、390×844、430×932，以及 844×390 横屏。独立浏览器设置 `isMobile`、`hasTouch`；Playwriter 使用 CDP 手机视口与触控模拟。
- 游客：10 个公开路由加注册面板，共 55 组布局测量；另有目录、目录跳转、受保护路由重定向，共 58 条结果。

这不是 iOS Safari、微信内置浏览器或 Android 真机验收。系统软键盘、输入法、刘海/底部安全区、真实弱网和文件选择器仍需真机确认。

## 已确认问题

### 1. 高优先级：跑腿发布抽屉固定 520px，常见手机宽度下内容被裁切

复现：登录后进入 `/tasks`，点击“张贴悬赏单”。

390px 视口实测：

- 抽屉宽度 520px，左边界 -130px，右边界 390px。
- 第一项输入框的左侧约 -80px，标题、字段名和输入内容的开头被裁掉。
- 底层页面仍可表现为没有整页横向滚动，因此仅比较页面 scrollWidth 会漏掉它。

根因：`frontend/src/views/TasksView.vue:99` 的 `size="520px"`；`frontend/src/styles.css:2215` 只约束 `.el-dialog`，没有约束 `.el-drawer`。

修复方向：抽屉宽度以视口为上限，内部表单保持可缩小；同时处理下一项的遮挡，单改宽度还不能保证可提交。

证据：`../../.claude/verification/mobile-2026-11-10/task-publish-390.png`（真实生产页面、未提交）。

### 2. 高优先级：底部导航盖在业务弹层上，能遮住提交按钮并在弹窗打开时切走页面

生产复现：跑腿发布抽屉打开后，底部“二手”仍可收到 CDP 触控事件，实际跳转到 `/goods`。店铺预约弹窗打开时，底栏同样位于遮罩上方。

使用相同已部署前端、合成账号进行客户端隔离复核：将跑腿抽屉内部滚到最底部后，提交按钮纵向范围为 792–824px，而底栏为 770–834px。按钮中心的命中元素属于底栏，确认不是单纯的视觉重叠。

根因：

- `frontend/src/styles.css:97`：`.content-shell` 建立 `z-index: 1` 的层叠上下文。
- `frontend/src/styles.css:2170`：其外部的手机底栏使用 `z-index: 2000`。
- `frontend/src/views/TasksView.vue:99`、`frontend/src/views/ShopDetailView.vue:63` 的业务抽屉/弹窗没有挂到 body，组件内部很高的 z-index 仍受父层限制。

修复方向：统一弹层挂载与层叠规则，保证业务弹层和遮罩高于底栏。不要只增大弹窗内部的 z-index。身份协议弹窗已经使用 `append-to-body`，本轮没有同样问题。

证据：`../../.claude/verification/mobile-2026-11-10/isolated-task-submit-covered-390.png` 和 `isolated-dialog-results.json`。该补充截图为浏览器合成身份布局测试，不是生产新增任务或真实提交。

### 3. 中优先级：日期组件的输入框适配不代表弹出的日历适配

运营页复现：`/admin/ops`，点击日期范围输入框。

- 390px 手机视口中，范围日历实际宽 646px。
- 文档滚动宽度变为 648px，第二个月的大部分区域在屏幕外；截图只能看到右侧日历的一小条。
- 输入框本身仍约 350px，超过带内边距标题卡片的内容区域，即使没有扩大整页也贴到了屏幕边缘。

普通用户预约也有短屏问题：`/shops/1` 打开服务预约的日期时间组件，在 844×390 横屏下，弹层高 423px，底部 OK 按钮位于 y=392–416，超出可见高度。这里记录的是几何超出，不声称已完整验证所有日历内部滚动补救方式。

位置：`frontend/src/views/AdminOperationsView.vue:10`、`frontend/src/views/ShopDetailView.vue:66`。`.wide` 或对话框宽度规则不会缩小 teleported 的日期面板。

修复方向：日期范围在手机上采用能适配的单日历/分开的起止日期方案；日期时间弹层同时限制可用高度并使确认区可达。保留桌面双月视图不受影响。

证据：`../../.claude/verification/mobile-2026-11-10/ops-date-range-390.png`（真实生产页面，数值及账号信息已隐藏）。

### 4. 较低优先级：个人信息页在 320px 宽度下横向溢出

复现：登录进入 `/profile`，视口 320×568。

- 容器可用宽度 292px，但子卡片保持 320px。
- 卡片左边界 14px、右边界 334px；文档滚动宽度 335px，比视口多 15px。
- 本轮 360/390/430px 和横屏检查没有同样溢出。

根因：`frontend/src/styles.css:1992` 的 `minmax(320px, 1fr)`，而手机主内容还保留左右各 14px 内边距。`.profile-grid` 没有手机单列可缩小覆盖。

修复方向：改为可缩小的网格最小值，或在手机断点使用 `minmax(0, 1fr)`。不需要重做个人信息页。

证据：`../../.claude/verification/mobile-2026-11-10/authenticated-results.json`。未保存含个人资料的页面截图。

### 5. 中优先级、并非手机专属：恢复会话的网络错误会直接清除登录态

根因：`frontend/src/stores/auth.ts:37–47` 的 `loadCurrentUser()` 对所有异常都调用 `clearSession()`，不区分网络中断、超时、服务端暂时失败和明确的身份失效。

客户端隔离复现：

1. 在独立浏览器中拦截全部 API，使用合成普通学生响应和不具备任何服务器权限的占位令牌。
2. 首次 `/auth/me` 返回本地合成成功响应，身份页显示正常，占位令牌存在。
3. 刷新时只让 `/auth/me` 发生 `connectionfailed`，不返回 401。
4. 页面仍跳转 `/auth?redirect=/roles`，占位令牌被移除。

这证明客户端将临时连通性问题当作登录失效。手机在 Wi-Fi/蜂窝切换时更容易遇到它，但本轮没有用真实移动网络断线来重现。

修复方向：只有明确的认证失败才清除会话；临时网络错误保留会话材料，提供重试/未能验证状态，同时不得把未验证用户放行到受保护内容。

生产浏览器后半程也有一次重新进入受保护页面转到登录的现象，但没有捕获明确的失败网络证据，因此不将那次现象直接归因于该代码。未重置密码或恢复提取任何真实令牌。

证据：`../../.claude/verification/mobile-2026-11-10/interaction-results.json`；该故障注入不访问生产业务 API。

## 已检查正常的部分

- 首页、跑腿大厅、商品列表/详情、店铺列表/详情、项目列表/详情、公开协议、登录页及注册面板，在 320/360/390/430px 和横屏测量中没有整页横向溢出。
- 游客底栏和“更多”目录可用；从目录触控进入店铺后抽屉关闭，匿名发布商品跳转登录并保留目标路径。
- 320px 公开协议的最右标签能通过标签栏的下一页按钮到达并触控切换。不能把标签栏内部横向排列误报为页面溢出。
- 身份、通知、信用、商品发布、商家工作台的已覆盖尺寸没有整页溢出；项目管理表格和后台其他表格的横向交互没有做完整验收，不因列超出容器就直接判定不可用。
- 协议弹窗在五种尺寸均能滚动到提交按钮，按钮未被底栏遮挡；默认未勾选时禁用，明确勾选后启用，没有实际提交。
- 钱包仍显示资金未开放；本轮没有改变资金开关。
- 公开页面和已保存的登录态检查未捕获应用 JavaScript pageerror 或 HTTP 4xx/5xx；部分自动化调用/等待曾超时，不宣称整个工具执行过程完全无错误。

## 未确认、不得作为已复现缺陷的静态候选

- 治理对话框的 120px 侧标签与数字输入，在 320px 下可能挤压；没有打开生产真实举报记录来确认。
- 运营校区分布数据行的固定最小列宽可能超出卡片；尚未用有记录的区间完成窄屏实测。
- 输入字体、小触控目标、系统键盘和安全区只能作为真机检查项，不能仅凭 CSS 就说某款 iPhone 一定无法使用。
- 本次既有账号的角色较全，不代表所有权限组合都完成了真实登录验收。新身份操作仅验证了隔离客户端交互，没有向真实账号提交协议。
- 真实发布、上传、接单、预约、审核等有副作用的流程没有在生产提交；本轮是布局和非破坏交互检查，不是全面端到端业务认证。

## 建议的修复顺序

先处理跑腿抽屉宽度和业务弹层层级，恢复手机上完整填写与提交的能力；再处理日期组件和弱网会话恢复；最后补齐 320px 个人信息网格。无需更换现有视觉设计或改动数据库。
