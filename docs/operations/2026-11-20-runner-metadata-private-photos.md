# 跑腿结构化信息与参与方照片 · 2026-11-20

## 范围

本轮将跑腿发布表单中的信息拆成结构化字段，并同步更新 Web 与原生小程序：

- **物品重量**：必填，客户端以公斤输入，服务端以整数克保存，范围 1–100000 克。
- **公开说明**：可选；旧任务仍兼容空值。
- **公开备注**：可选，最多 1000 字；不应填写密码、房间号或私人联系方式。
- **取件码**：可选，最多 120 字，只在参与方工作区返回，保留前导零。
- **物品照片**：发布者可选上传最多 3 张 JPEG/PNG 请求照片。
- **送达凭证照片**：`PHOTO_AND_CONFIRMATION` 任务由实际接单者在 `DELIVERING` 或 `DELIVERED` 阶段上传，至少一张后才能提交送达凭证。

“委托事项”和“起止路线与时限”已在 Web 和原生发布流程中合并为同一任务信息区；后端仍保持一次 JSON 创建任务请求，不拆成多个业务对象。

## 隐私边界

公开任务列表和任务摘要只返回重量、公开说明、公开备注、路线、时限、报酬和任务状态，不返回取件码、参与方联系方式、照片元数据、照片哈希或存储路径。

任务工作区仅允许发布者和实际接单者访问。照片下载经过 JWT 参与方校验，使用私有、不缓存响应；普通管理员不因管理权限自动获得参与方照片权限。通用文件绑定不向参与者开放绕过入口。

客户端：

- Web 通过带 Bearer Token 的 Blob 请求读取照片，并在卸载时释放对象 URL。
- 小程序通过 `wx.uploadFile`/`wx.downloadFile`，只在用户主动选择照片后执行，不自动保存到相册。
- 上传失败保留任务 ID和稳定的 clientRequestId，只重试未成功照片，不重新创建任务。
- 退出、切换账号、页面隐藏会清理私密取件码、照片临时路径和证据状态。

## 后端合同

V18 保持 V1–V17 不变，新增 `task_delivery_photos` 及重量/备注/取件码字段。主要接口：

- `POST /api/tasks`：`weightGrams`、`notes`、`pickupCode`。
- `POST /api/tasks/{id}/request-images`：发布者请求照片。
- `POST /api/tasks/{id}/evidence`：实际接单者送达照片。
- `POST /api/tasks/{id}/evidence/submit`：提交送达凭证并进入待确认。
- `GET /api/tasks/{id}/evidence/{photoId}`：参与方下载原始图片。
- `GET /api/tasks/{id}/workspace`：参与方获取私密字段、事件和证据摘要。

照片使用配置的 `CAMPUSHUB_FILE_ROOT` 下的随机相对存储键，校验 JPEG/PNG 内容、单张 5 MiB、每类最多 3 张、任务合计最多 15 MiB；不把文件系统路径返回给客户端。

## 未完成的正式发布门槛

本轮未部署、未改 DNS、未向生产或杭州恢复演练写入照片，也未重新上传微信版本。正式启用前仍需：

- 生产持久化上传卷的容量、备份、恢复和权限验证；
- 正式 HTTPS、微信 `request`/`uploadFile`/`downloadFile` 合法域名配置；
- 相册/相机隐私声明、照片用途、参与方可见范围、保留期限和删除规则；
- iOS/Android 真机安全区、相册权限、网络切换和上传失败验收；
- 真实微信开发者工具上传版本的重新验证。
