## 二手订单的「查看商品」规则（验收后的产品决定）

「我的订单 → 查看商品」按 `objectId`（原商品 `goods.id`）进入卖家的**当前商品页**，不是成交时的页面，也不会找卖家的另一件同名闲置。订单记录仍提供针对该笔成交的评价和投诉。

- 同一 ID 的标题、说明、标价和展示图由卖家在原记录上修改。已售商品也可编辑，修改不会重新上架或重新成交。图片列表和文件请求使用与详情相同的查看权限；查看图片不额外开放卖家联系方式。
- 商品编辑不生成版本，不复制照片到订单。V22 只为实际确认的线下成交保存一个金额；已有二手订单沿用自己的 `amount`。迁移只为能核对买家的历史成交意向填入原系统当时所显示的金额，不给未成交或缺买家的意向补造价格。
- 「下架」只停止出售，不是删除。「删除商品」需卖家确认；如仍有未结束的历史交易订单，暂不允许删除。删除后释放当前图库的图片数据、保留商品 ID 与订单关系；两端收到该商品详情的 HTTP 410 才显示「该商品已删除」。无权查看、未知编号和断网不会被当作删除。已完成订单仍可评价和投诉。
- 新规则复测：后端 145/145、Web 69/69、小程序 64/64；Web 构建与官方 WXML/WXSS 编译通过。独立 MySQL 8.4 实测 V21 → V22：原成交金额 12.34，改标价为 25.50 后订单仍为 12.34；历史无匹配买家的意向未补造成交金额。本轮没有生产或真机操作。
- 下面的 Fable 结论记录的是变更前的候选。原 P1 的“成交后冻结卖家图片”**不再是验收标准**，改按本节的同 ID 最新内容、原成交价、删除提示和权限边界验收。其他真机和隐私发布条件未因此取消。

## 使用路径
- Web：我的书院 → 我的订单。小程序：底部「个人」→ 我的订单 → 全部或状态快捷入口。原 `/pages/pass/index` 地址保留；另有独立「二手」Tab。
- 类型包括跑腿、二手、预约、宣传。个人的待评价只计本人尚未评过的已完成交易；宣传无交易对方，不提供评分。卖家每件在售商品只占一行，详情选定实际买家后确认成交；未选中的意向结束，历史无买家售出不补造订单。
- 发单人可在履约台修改尚未有人报名或接单的跑腿；接单前可撤下，有报名时通知报名者，已接单不允许单方删改。撤下保留记录，不清空其他人的履约历史。
- 已完成的具体订单可评价或投诉；店铺与宣传详情可举报内容，两者均到同一治理队列。完成预约的顾客评价进入商品口碑；店主对顾客的互评不会改变服务评分。店铺分=有评价服务的各自均分的算术平均（不把未评分服务当作 0），展示保留一位。
- 店铺封面 1 张、服务商品/闲置/宣传各最多 3 张，均可不传。图片选用 JPG/PNG，上限 5 MiB，解码后重新编码，剥离原始元数据。图片与跑腿私密照片相互隔离；宣传已通过审核后换图会退回待审。

## 数据和运维
V20 为已购评价增加可空商品关联、为新投诉增加可空唯一去重键，不迁移或重写旧泛评价。V21 用单独 `catalog_images` 表保存已去除元数据的图片字节与归属；先按父对象鉴权，再取字节。这样插入、限制张数和删除与事务同步，不留未绑定磁盘文件；上限使单页有界。容量和备份要按实际图片使用量评估，二进制数据库备份应使用 `mysqldump --hex-blob`。V18 跑腿证据仍使用原有受保护上传卷，备份不能遗漏。正式站两层代理、Spring 和开发 Nginx 均需允许 6 MiB 请求体；协议及隐私指引应核对新增的公开商品、店铺与宣传图片用途，不能沿用“所有图片仅任务双方可见”的描述。

隔离验收使用一次性 MySQL 8.4（V1–V21 逐文件应用、真实订单投影查询）、H2 Spring 集成测试及合成账号、回环访问的本地浏览器和微信开发者工具。正式真机/平台提审不在这些结果之内。

### 其他观察（不计作 P1）

- **评分：** 原生直接拼接数值，整数显示为「5 分」而非 Web 的「5.0 分」。建议加 `4、5 → 4.5` 及多商品小数均分的跨库断言。既有测试验证了 `5、5、5` 与 `1` 两个商品的店铺分是 `3.0`；本轮没有实测 H2 对 `AVG(INT)` 的小数行为，不将数据库截断写作已证实的缺陷。
- **投诉处理：** `AdminGovernanceView.vue:52–59` 的列表显示原因和处理备注，未直接展示用户提交的详细说明。建议在不进入违规处置流程的情况下即可展开原文。
- **原生交互：** 已关闭/屏蔽宣传仍可显示图片编辑按钮，服务端会拒绝；订单详情用列表旧行而不是最新详情计算履约台链接，刚被选中的报名人可能需要刷新。静态包检查只匹配 `wx.uploadFile(...)` 等直接调用，不能单独证明动态调用位置得到检查。
- **图片兼容性：** 编解码会拒绝非标准 `image/jpg`，重编码未显式按 EXIF 方向旋转；真机若遇到误拒或旋转，应以不放松图片解码/尺寸验证为前提修复。
- **已排除的审阅疑点：** 复核 `ProjectAdService.java:71–76,201–203` 与 `ProjectAdRepository.java:10–12`，浏览计数先取得 `lockById` 悲观写锁，图库写入也锁定同一父行。故“无锁浏览量刷新覆盖换图待审状态”不作为本候选的已确认缺陷。
