## 修复

### 原生按钮默认宽度覆盖自定义宽度

实际模拟器首屏出现右侧“立即抢单”被裁切。通过官方自动化测量：卡片宽约372 CSS px，副券宽约104px，但原生按钮仍为184px，超出副券边界。

原因是微信 v2 默认按钮宽度规则的优先级高于已有类样式。已补充显式按钮class及足够优先级的基础宽度/边距规则，并让副券按钮沿容器伸展；主操作按钮和禁用态同时统一处理。

- `app.wxss`：覆盖平台默认按钮宽度及禁用态对比度。
- `pages/tasks/index.wxss`：副券按钮在内部伸展，不超出票卡。
- 各页面与协议组件：主按钮显式 `primary` class，不依赖平台默认尺寸。
- `tools/check.cjs`：新增所有按钮必须显式带样式class的包检查。
- `tools/native-smoke.cjs`：新增实际点击区域不超出票卡的几何断言，修复前失败、修复后通过。

### 原生组件定位与样例AppID

- 给协议及关键底部抽屉添加稳定ID，使原生自动化能跨组件作用域定位，不用直接调用业务处理函数冒充用户点击。
- `touristappid` 在当前工具报 APPID_ERROR；改用已授权AppID仅运行本地隔离项目，并更新预览校验，未增加真实API调用。

## 9项实际交互检查

最终交互运行全部通过；测试数据只在样例内存中变化：

1. **跑腿按钮几何**：按钮点击区域完整落在车票卡内。
2. **游客登录与跑腿协议**：点抢单进入登录页，原生输入框输入样例账号；回到跑腿后打开协议。未勾选时提交禁用，点击标签勾选后启用，提交后样例跑腿角色生效。
3. **跑腿接单**：确认抽屉提交后进入履约详情，识别当前人为接单者，下一步为“出发取件”。
4. **服务预约与联络可见性**：预约前无联系信息；原生预约抽屉可见，提交按钮在底部区域内，样例预约成功后才显示主理人联系方式。
5. **宣传收藏与留言**：实际点击收藏、打开留言抽屉、输入并提交；详情更新收藏和公开留言，不冒出原本不可见的联系方式。
6. **通行证与记录**：跑腿身份点亮、顾客预约显示“等待店主确认”、通知为空时显示正常空状态。
7. **三步发布跑腿**：输入路线、委托说明与金额，推进到确认页，发布后进入样例本人任务详情。
8. **宣传本机草稿**：输入标题并“存为本机草稿”，不创建服务器ID、不进入审核。
9. **商家身份核验**：主动勾选商家协议后，通行证显示“核验中”，不在本地擅自授予商家角色。补齐样例API对待审核申请的保存，避免离线演示在刷新后丢失该状态。

## 可复用命令

在仓库根目录、Node 22+，先生成样例：

```bash
node miniprogram/tools/make-preview.cjs
node miniprogram/tools/check-preview.cjs
```

通过用户已安装并启用服务端口的微信工具打开**样例项目**：

```bash
"C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat" auto \
  --project "D:/USTC/2026Spring/数据库系统概论/实验二/campushub/.claude/verification/native-miniprogram/offline-preview" \
  --auto-port 9420 --port 37972
```

```bash
WECHAT_CAPTURE=0 node miniprogram/tools/native-smoke.cjs
node miniprogram/tools/capture-native-gallery.cjs
```
