## 切换门槛与回退

1. 新机已生成独立 DB/JWT 配置。根据本日用户决定，杭州不再承接 API-Transfer-Station 的历史支付回调。不配置旧凭据、不轮换香港密钥、不启用新的支付宝应用；新站网关对旧回调返回 410，旧订单、流水和回调事件仍随库迁移。`./compose config --quiet` 可无输出校验，禁止打印展开的配置。金融、重置、mock 开关继续关闭。
2. 准备旧域名网关：仅对旧 CampusHub 主机名作修改，切换时历史回调路径直接返回 410，不得转发、重定向或返回伪成功。其余路径按迁移策略重定向。先备份并验证差异与 Caddy 配置，不要改其他站点或提前启用转发。
3. 完成窗口准备后，排空旧 CampusHub 并仅停旧 CampusHub 后端；对其独立 MySQL 开启 `super_read_only`。不停止共享网关或其他项目。用 `frozen-snapshot` 导出压缩数据库、逐表计数、上传档案及哈希，不要把私有档案放进 git 或控制台；SSH 传输并校验 SHA256SUMS。若传输/恢复失败且杭州从未接收新写入，保持杭州入口关闭，将旧库只读设置恢复为原值并启动旧后端。
4. 在**全新空生产卷**先仅启动 MySQL，再恢复 V16，核对表集合、逐表计数和逐文件校验。不得覆盖演练库、在已迁移的空基线重放 dump 或把不完整备份当成功。启用生产专用 SMTP socket，将 Web 放在回环入口，在静态公网入口继续关闭时启动后端、检查 V17/V18、金融开关、匿名/私有 API、代理上传上限和 SMTP TLS 启动认证。完整投递另需受控收件地址。
5. 仅在目标验收通过后切杭州网关和旧域名路由。保留旧数据库停写。查证旧回调路由均返回 410、不进入业务服务，避免真实资金验证；检查新网页、备案、证书和附件隐私。新机一旦接受任何写入，禁止直接打开旧库或反切 DNS，先冻结杭州并保全增量，协调数据回迁/向前修复。
