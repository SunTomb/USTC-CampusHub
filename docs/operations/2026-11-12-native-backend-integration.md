# 原生小程序真实后端隔离联调 · 2026-11-12

## 结论

原生小程序跑腿主链路已在**一次性可写、仅合成账号的 H2 后端**上完成真实接口联调。联调使用正式 `miniprogram/src/` 的字节一致复制工程，开发版 API 根地址临时指向本机回环地址，经 SSH 隧道到旧服务器上的隔离 Docker 容器；没有连接旧生产容器、杭州恢复演练容器，也没有上传或发布小程序。

这不是生产验收、备案验收或真机验收。正式 API 默认仍为 `https://ustc.suntomb.cn/api`，在域名和 HTTPS/request 合法配置完成前，不应把回环联调地址写入体验版或发布版。

## 后端实现

- 新增 V17：`reward_tasks.completion_code_attempts` 与 `completion_code_issued_at`；V1–V16 未修改。
- 跑腿任务发布拒绝负报酬、过期截止时间和非零任务保证金。
- 抢单、报名、选择报名人、履约推进、完成确认和管理员关闭任务使用任务级悲观锁；报名重复提交返回既有记录，不产生额外行。
- 合法履约顺序限定为 `ACCEPTED → HEADING_TO_PICKUP → PICKED_UP → DELIVERING → PENDING_CONFIRMATION`，同时兼容 `DELIVERING → DELIVERED → PENDING_CONFIRMATION`；终态不能再次推进。
- 工作区只允许发布者或实际接单者访问，返回参与方明确填写的微信/QQ和事件；公开任务摘要不返回联系方式、完成码或完成码哈希。
- 完成码仅发布者生成，服务端只保存 BCrypt 哈希；有效期 30 分钟，输错 5 次后锁定，重新生成会重置尝试次数，成功核销后清除哈希。
- 管理员关闭任务也通过同一任务锁执行，不会以旧快照覆盖接单关系；已完成任务不能被重复关闭。
- 选定接单者的工作区会过滤其他报名人的 `APPLIED` 留言，发布者仍可查看完整事件审计。
- 联系方式修改和通知标读归属校验保留在同一隔离测试范围内。

## 真实原生联调流程

联调脚本位于会话验证目录，不属于正式小程序包：

`.claude/verification/native-miniprogram/real-api-integration.cjs`

合成账号为临时 H2 初始化账号，密码只用于本次隔离测试，不是生产凭据：

1. 合成发布者通过原生 API 登录并发布 `COMPLETION_CODE` 跑腿任务。
2. 发布者从原生任务工作区读取自己的联系方式；公开摘要确认没有私密字段。
3. 合成接单者通过原生协议接口阅读并同意跑腿协议，刷新 JWT 角色后抢单。
4. 接单者从原生页面依次推进四个合法履约状态。
5. 发布者通过原生页面生成六位完成码；码只留在页面内存。
6. 接单者通过原生页面输入完成码并核销，任务进入 `COMPLETED`。
7. 完成后的参与方工作区仍能读取双方允许展示的联系方式和事件时间线。
8. 陌生合成账号请求同一工作区得到 HTTP 403。

最近一次真实联调结果：**22 项检查全部通过**，包括协议开通、发布、私密工作区、合法状态推进、完成码生成/核销、事件时间线及陌生用户拒绝。

## 隔离与清理

- 后端容器：临时 H2，端口只绑定旧服务器回环路径，再经 SSH 隧道访问。
- 外部副作用：邮件关闭、金融功能关闭、Beta 重置关闭；没有生产邮件、支付、数据库或用户写入。
- 小程序工程：使用正式源码的验证复制，不上传、提审或发布。
- 联调结束后应删除临时后端容器、内部 Docker 网络、SSH 隧道和验证复制目录；不得把合成账号或回环地址带入体验版配置。
