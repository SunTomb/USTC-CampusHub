# 原生小程序首版实施记录 · 2026-11-11

## 已确认方向

依据 `2026-11-11-campushub-miniprogram-architecture-and-ui-guide.md` 和用户本轮要求，独立开发原生微信小程序，不复制 Web 管理导航或手机网页布局。

- 四个原生 Tab：跑腿、小店、宣传、通行证；无门户 Hero、无汉堡目录、无管理后台、无资金操作、首版不放二手业务入口。
- 视觉：宣纸暖白、深墨蓝、少量鎏金，跑腿车票副券、工作室橱窗、宣传展板、深色通行证。列表优先操作与信息密度，不做大横幅宣传。
- 交互：原生下拉刷新、校区胶囊、65%–85%底部抽屉、明确的提交/错误/重试反馈；轻微抽屉过渡和成功触觉反馈，不依赖鼠标。
- 技术：微信原生 WXML/WXSS/JavaScript（CommonJS + JSDoc），10 个页面，微信开发者工具直接导入。现有机器有开发者工具，无需为框架安装新依赖。
- 通知、个人资料与“我的单据”收在通行证分段/抽屉，避免指南示例虽然写“10页以内”却列出11页的问题。
- 默认目标 API `https://ustc.suntomb.cn/api`，正式域名尚未上线；独立开发配置允许本机服务或SSH回环隧道，只对开发版生效，正式版不使用演练替身。
- 保留校园邮箱/用户名登录与 JWT，不伪装成已完成微信一键登录。不生成 AppSecret，不读取生产令牌。

## 以真实实现纠正建议

- 只对明确 401 清理登录；403 是权限不足，不一概登出。网络/超时保留会话，私人操作必须等待验证，旧响应不能覆盖新会话。
- 不写“10秒读完协议”，不把信用100硬编码成真人分数，不伪造热门服务/评论数；所有角色协议从后端读取实时版本和全文。
- 图片只展示安全的已存在资源；未有原生上传端点前，不出现选相册/上传按钮。
- 店主只做轻量预约接单/开始/完成，不搬运店铺经营后台或站务审批。
- 已开通身份不补签，商家申请提交后等待站务核验。资金边界与既有历史记录保持不变。
