### 独立离线样例预览

为了在正式域名尚未开放时检查布局，可生成单独的预览工程：

```bash
node miniprogram/tools/make-preview.cjs
```

从仓库根目录运行，输出到 `.claude/verification/native-miniprogram/offline-preview/`。在开发者工具中**另行导入该目录**。当前工具不接受 `touristappid`，样例工程沿用已授权的 AppID 仅作本地打开；这不会上传或发布代码。每页标题带“样例”，使用合成同学/店铺/任务；演示登录可输入任意非空用户名和密码，绝非真实登录。所有业务 API 在内存中模拟，没有网络转发、真实发信、支付或业务写入。

该工程用于本地观察卡片、抽屉和导航，**不能上传、审核或发布**，也不证明后端业务流程已通过。样例不在 `miniprogram/src/` 内，正式包不包含它。若需真实数据联调，仍导入正式工程并使用合法隔离环境。

### 本地联调配置

仅在开发版 `envVersion=develop` 时，允许在开发者工具控制台设置回环地址：

```js
wx.setStorageSync('woke_development_api', 'http://127.0.0.1:28180/api')
```

设置后重新编译。该值只用于开发者工具与本机后端/SSH隧道，不适用于手机上的 localhost。生产/体验版忽略该覆盖，始终使用正式 HTTPS 域名。每个 API 根地址使用独立令牌存储键，避免把演练令牌发送给其他环境。

演练环境 Nginx 目前阻止业务写入，因此经现有隧道只能做允许的只读访问和合法账号登录；**不要为了测试小程序而自动解除演练限制**。写流程需独立授权的可写隔离环境。开发工具跳过域名检查只可作为本地调试选项，不能据此宣称正式网络验收通过。

## 页面与功能

| Tab | 页面/交互 |
|---|---|
| 跑腿 | 发布、抢单或报名、履约；发单人可在接单前撤下，无报名时可修改。 |
| 二手 | 浏览、发布闲置与图片、联系卖家；卖家从意向中选定成交人。 |
| 小店 | 校区/类别/关键词筛选，真实已发布服务的价格预览，服务详情与原生日期/时间预约抽屉，预约后按接口决定展示联系复制入口 |
| 宣传 | 精选横卡、类别/校区/关键词筛选、纯文本详情、收藏/取消、公开留言、按服务器规则查看联系方式；本机草稿及明确提交审核 |
| 个人 | 我的订单（跑腿、二手、预约、宣传）、评价与投诉；身份、通知及账号设置。 |

身份开通协议从后端读取，不硬编码版本。初始不勾选，主动同意后提交；跑腿/闲置发布者可自动开通，商家仍等待站务核验。已开通角色不补签。闲置发布者可直接在小程序上架商品。

协议抽屉使用原文及版本，不用“10秒读完”等诱导文案。信用分来自接口，缺失时显示“—”，不伪造等级。列表无记录时显示真实空状态。

## 与设计指南的必要差异

指南作为视觉/产品方向，不把其中超过现有服务能力的建议伪装成已实现：

1. 指南写“10页以内”但示例有11页；通知、账号编辑和我的记录合并进通行证分段/抽屉，当时为 10 页。本地新版增加二手、订单和店内商品详情共 5 页。
2. 采用指南允许的原生方案，无需另装 uni-app/Pinia/Vite。不是网页套壳，不使用 web-view。
3. 403 表示权限不足，不自动清除 JWT；仅明确 401 清会话。网络错误保留令牌但不显示未验证私人内容，并提供重试。
4. 跑腿完成码由服务端生成、有效期30分钟且支持替换失效；接单同学仅可在等待确认阶段核销，连续输错5次会锁定。完成码只在发布者当前设备内存中显示，不写入本机存储或私密工作区。
5. 已增加按当前JWT用户读取的发布者任务历史接口 `/tasks/mine`。“个人 → 我的订单 → 跑腿”使用服务器数据，支持跨设备，不再依赖本机ID列表。
6. 跑腿公开摘要不包含联系方式、完成码或事件；发布者与实际接单同学通过服务端授权的私密工作区读取双方微信/QQ和履约事件。非参与者不请求或展示该工作区。
7. 用户资料更新已提供用户名/昵称和微信/QQ联系方式的分开保存接口；个人页分别保存并校验至少一种联系方式。邮箱、头像仍是只读，不出现不可用保存入口。
8. 宣传 `create` 当前直接返回 `PENDING_REVIEW`。**“存为本机草稿”不调用服务器写接口**；明确提交后才创建/更新并进入核验。创建超时结果不明时保留不确定状态，要求核对，不自动重建重复帖子。
9. 跑腿已接入真实的参与方照片上传/下载接口：发布者可上传请求照片，接单者可在送达阶段上传送达凭证；照片仅参与者可见，客户端不保存到用户相册。公开展示图走独立的 catalog-media 接口，不使用任务证据地址。
10. 不接入 wx.login/jscode2session，不生成 AppSecret；使用已有校园账号与邮件验证码注册，不冒充微信一键登录已实现。

## 数据与权限

- `lib/request.js` 只接受本端支持的相对 API 类别，阻止绝对 URL、后台和资金请求路径。
- 严格处理 HTTP 状态及 `success`，网络失败提示中文；访客浏览不因失败自动跳登录。
- 退出/切换用户清除私人页面数据，晚到的旧请求不能覆盖新会话。
- 角色开通、预约、发帖等带忙碌锁，避免连点；身份同意版本错误须重新加载并重新勾选。
- 仅复制服务器明确允许展示的联系方式。服务预约联系快照按顾客身份呈现，通知只对当前列表中的本人记录标读。
- 前端权限是交互保护，不是服务端鉴权替代。后台已知通知归属/跑腿状态等授权缺口需在公开小程序前另行修复并联调。
- 用户文本使用普通 `text/view` 展示，不把 HTML 当作富文本执行。
- 密码、验证码不持久化；提交后清理。令牌仅保存在微信设备存储，草稿和本机任务记录按账号及 API 环境隔离；存储失败会提示，不能宣称跨设备持久化。

## 原生模拟器自动化

用户已开启工具服务端口。本次使用 Node 22+ 内置 WebSocket 驱动官方小程序自动化协议，无需安装新的自动化依赖。先生成并检查独立样例，再用开发者工具 CLI 的 `auto` 命令打开样例项目（不要 upload）：

```bash
node miniprogram/tools/make-preview.cjs
node miniprogram/tools/check-preview.cjs
"C:/Program Files (x86)/Tencent/微信web开发者工具/cli.bat" auto --project "<本仓库绝对路径>/.claude/verification/native-miniprogram/offline-preview" --auto-port 9420 --port 37972
```

`native-smoke` 在写动作前拒绝非离线 API 根地址，测试在本机样例中运行；`WECHAT_CAPTURE=0` 将交互断言与偶发超时的模拟器截图接口分开。`capture-native-gallery` 只采集真实模拟器画面，不生成或绘制假界面。结果位于 `.claude/verification/native-miniprogram/native-acceptance/`，包含9条流程、运行时异常记录及四Tab截图。
